# Мониторинг Ubuntu на ESP32

Сборщик `services/monitoring/src/server_monitor/collector.py` каждые 2 секунды читает `/proc`, `/sys` и
состояние файловой системы `/`. Он атомарно заменяет `/var/lib/synch-monitor/status.json`.
Systemd запускает его от `synch-monitor`, без сетевого порта, с ограничением записи
каталогом состояния. Caddy публикует JSON по `/monitor/status` с Bearer-токеном и
`Cache-Control: no-store`.

## Контракт

| Поле JSON | Значение |
| --- | --- |
| `schema_version` | `1` |
| `generated_at` | Unix-время измерения, секунды |
| `cpu_percent` | Средняя загрузка CPU за интервал; `null` при недостоверной дельте |
| `ram_used_bytes`, `ram_free_bytes` | Использованная и доступная приложениям память |
| `disk_free_bytes`, `disk_total_bytes` | Доступное обычному пользователю и полное место на `/` |
| `disk_util_percent` | Доля времени занятости устройства; `null`, если измерение недоступно |

Disk I/O не измеряет пропускную способность или SMART. Для раздела используется
родительское блочное устройство. В сложных схемах хранения можно передать `--device`;
неподдерживаемое автоматическое определение завершает запуск с ошибкой.

ESP32 опрашивает HTTPS примерно каждые 5 секунд. TLS использует встроенный набор CA;
перед запросами требуется время NTP. Метрики старше 20 секунд скрываются. HEALTH отдельно
проверяет главную страницу: HTTP 200 не доказывает исправность всех API. Сеть выполняется
в отдельной задаче; экран показывает часы 5 секунд, сервер 10 секунд. Время — Самара, UTC+4.

Неудачный запрос сохраняет последний корректный снимок до истечения этих 20 секунд.
Время неудачной попытки не продлевает срок свежести. При повторной попытке видна надпись
`METRICS RETRYING`, при неверном токене — `METRICS AUTH ERROR`. HEALTH показывает
числовой код транспортной ошибки. Метрики запрашиваются перед HEALTH; лимиты TCP и чтения
составляют 5 секунд, TLS handshake — 8 секунд. USB-журнал на 115200 бод содержит результат,
длительность, RSSI, доступную память, возраст снимка и подробности ошибки TLS без токена.

## Подготовка на Windows

Из корня этого репозитория:

```powershell
uv sync --locked
uv run --locked python scripts/check.py
uv run --locked python scripts/prepare_monitor.py --domain dedvnutri.space
```

Подготовка создаёт `.env.monitor`, отсутствующий `esp_software/monitor_secrets.h` и
`.local/monitor-deploy.tar`. Существующий токен сохраняется; конфликт токенов останавливает
команду. Существующий заголовок прошивки не переписывается, в том числе при изменении
`--domain`: адреса в нём нужно согласовать отдельно. Для новой установки генерируются
32 случайных байта. Архив содержит секрет и не предназначен для публикации.

Если настройки Wi-Fi ещё не заданы, скопируйте `esp_software/secrets.example.h` в
`esp_software/secrets.h` и заполните SSID и пароль. Приватные заголовки и `.env.monitor`
исключены из Git. На Windows ограничьте доступ к этим файлам своей учётной записью;
Unix-права `0600` не заменяют Windows ACL.

## Установка и обновление на Ubuntu

Используйте полный checkout проекта и приватные `.env`, `.env.integration`,
`.env.monitor`, описанные в [инструкции эксплуатации](docs/OPERATIONS.md).
Архив `.local/monitor-deploy.tar` содержит только сборщик, установщик, unit и токен;
это приватный пакет для сборщика, а не самостоятельная поставка сайта.

После передачи checkout и настроек на VPS установите сборщик:

```sh
cd /opt/synchronisica/repo
python3 services/monitoring/src/server_monitor/install.py
python3 -m scripts.stack config --quiet
```

На Ubuntu используется системный Python без внешних зависимостей. Установщик сохраняет
предыдущие файлы с суффиксом `.previous`, проверяет unit и перезапускает службу.
Автоматического отката установки службы нет. При ошибке восстановите эти файлы,
выполните `systemctl daemon-reload` и `systemctl restart synch-monitor`, проверьте журнал.

Маршрут `/monitor/status` и панель подключаются через единый production-стек
`scripts.stack`; отдельной активации мониторинга нет. Для обновления используйте
инструкцию эксплуатации: пересоздание Caddy кратко прерывает HTTPS-соединения.
Перед ним сохраните конфигурацию и состояние, проверьте Compose/Caddy.
После обновления проверьте 401 без токена, 200 с токеном и свежесть снимка.

Панель доступна на `https://dedvnutri.space/monitoring/` по отдельному паролю Beszel.
История ресурсов и проверки сайта, SQL-readiness и свежести ESP32 собираются отдельно
от двухсекундного JSON. Внешние уведомления пока отключены по выбору пользователя.
Zabbix Agent сохранён; подробные systemd-сведения через Beszel Agent не подключены.

## Прошивка

Главный файл `esp_software/esp_software.ino` соответствует имени каталога согласно
[спецификации Arduino](https://docs.arduino.cc/arduino-cli/sketch-specification/).
Профиль `sketch.yaml` фиксирует ESP32 3.3.12 и версии библиотек дисплея.

```powershell
arduino-cli compile --profile esp32 --warnings all --build-path .local/arduino-build ./esp_software
```

Если CLI отсутствует в PATH, используйте `resources/app/lib/backend/resources/arduino-cli.exe`
из установленной Arduino IDE. Команда компилирует прошивку без загрузки на плату.

Проверка сохранения последнего снимка, ошибок, восстановления, границ свежести и
переполнения `millis()` выполняется без платы. Из Visual Studio Developer PowerShell
с установленными C++ Build Tools:

```powershell
./scripts/check_esp_state.ps1
```

| ST7735 | GPIO ESP32 |
| --- | --- |
| SCK | 18 |
| MOSI | 23 |
| CS | 27 |
| DC | 26 |
| RESET | 25 |

Профиль дисплея `INITR_BLACKTAB`, поворот `1`, буфер `160×128`. Питание и модель платы
сверяйте со своей схемой; таблица описывает текущий код.

Компиляция 2026-10-11 прошла без предупреждений: 1 160 248 байт flash (88%), 51 024 байта
глобальных данных (15%). Прошивка загружена на COM9, контрольные суммы записи проверены.
Собранные бинарные файлы содержат настройки Wi-Fi и токен, публиковать их нельзя.
USB-журнал после загрузки подтверждает HTTP 200 для HEALTH и метрик с возрастом 0–2 секунды.
Пользователь подтвердил смену экранов, правильное время, отображение метрик и восстановление
после EN/RESET. Отключение Wi-Fi, устаревшие метрики после остановки сборщика и неверный
токен на устройстве пока не проверялись; тест состояния проверяет ошибки и срок свежести
без физической платы.
